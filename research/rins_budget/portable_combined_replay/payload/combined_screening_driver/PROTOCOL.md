# Frozen combined screening campaign

This is an isolated implementation of the prospective combined design and its pre-outcome seed amendment. Source/mock review does not run numerical work. An explicit user CLI invocation selects each one-use numerical phase. No C++ source, build, old protocol, global data manifest, or dataset is changed.

A starts from empty pairs and runs cold integer separation, with root child credit false and baseline separator 0760ccab. B starts from empty pairs, permits at most three cold dual-simplex LP calls at 10 actual process seconds each / 30 aggregate, then fresh MIP masters, root credit true and optimized separator 1833d1f. Both use the exact same reviewed executable and DSOs, original outer-gap policy and logging, two threads, parallel off, initial-root IPX off, 1% target, and identical MIP options except the root-credit boolean. Only validated eligible pairs and the existing valid integer-master bound ledger persist within an arm. No point, LP bound, basis, rating table, topology/factorization or historical pairs carry over.

The measured mathematical implementation is retained. model_stage.py differs only in its leading module documentation; SOURCE_IDENTITIES.json records original/public raw hashes and normalized AST/function-body equivalence. primal_and_bound.py and credit_events.py remain byte-identical to the measured sources. Canonical loaded-matrix equality, generator, original complete source checker, finite/status checks, conservative bound allowances and (U-L)/max(abs(U),1e-10) <= .01 are preserved. Production retains 36 hours, 89 buses, 12 units, 210 lines, all 192 source-listed outages and 14,721 eligible pairs. The only added data is exact-byte November from the separately reviewed supplemental design directory.

Every scope preparation, generation and complete check runs in a fresh pinned Python interpreter with -B -s. stage_child.py checks the fixed plan, allowlisted arm record, exact source paths and hashes, then compiles contracts, the selected separator, primal_and_bound and model_stage from verified bytes. It rejects any existing module registration. Startup/end runtime checks and exact loaded-module/input/output receipts are symmetric. Scope preparation is per arm; there is no shared numerical or source cache. The selected separator modifies only its independent source scope/direct separation; the original full source checker still runs for every emitted complete MIP point. Selector receipts are separate from unchanged checker JSON output.

Each production arm has 600 actual aggregate solver-process seconds; LP time is inside that allowance. Reaped processes are debited before checks. Solver watchdog overshoot remains charged and cannot create a complete certificate. Helper/resource/integrity failures and cancellation stop before a later arm. Ordinary incomplete/timeout outcomes retain their safe counterpart, then confirmation stops with all later pairs explicitly unrun. Incomplete arms have no time ratio and are never replaced by the budget.

The co-primary E2E endpoint is the reviewed in-program standalone-equivalent interval: before arm directory/runtime/source work through final checks and durable summary fsync, plus full common definition-import/plan-archival time charged to each arm. Each receipt reports generation/readback, source scope, LP checks, integer checks, LP and MIP solving and remaining overhead. Pair archival has a separate receipt. The outer phase receipt starts before phase checks/marker and includes pair serialization and separately charged tiny replay. Interpreter launch itself is not claimed. A full phase is not benchmark timing.

The fixed one-use campaign directory is run_v1; exclusive phase markers prevent implicit rerun, restart or alternate output/seed selection. The CLI only exposes --run-reviewed --phase tiny|development|confirmation. The flag acknowledges the frozen protocol and its resource costs; no external approval file is used. A failed campaign cannot be rescued by retries, tuning, output replacement, changed seeds/budgets or credit-policy changes.

Tiny: one AB pair, 20 actual solver seconds per arm, two-second MIP containment grace and twenty-second helper watchdog. A requires zero LP calls, empty first integer pairs and at least two integer rounds discovering missing pairs. B requires LP-discovered pairs and a subsequent fresh integer master. Both require full source certificates at objective 660 and selected-module identity receipts. Successful tiny runs are followed by separately charged exact A/B complete-check equality replay on every tiny witness. Tiny proves wiring, not speed or natural credit activation.

Development: February seed 0, AB, fresh 600 seconds per arm. Both complete certificates, valid resource/credit telemetry, and actual B applied cap or exhausted-credit skip are mandatory, alongside at least 20% paired improvement on both solver and standalone-equivalent E2E. Failure ends this route. Development remains familiar rather than held out.

Confirmation, only after a separate explicit CLI invocation and a passed development gate: November1 BA, August1 AB, February3 BA, February4 AB, November2 AB, August2 BA, August3 AB, February5 BA, November3 BA. For each date separately, all three complete pairs must improve both endpoints strictly, and median of paired reductions must reach 30% for each endpoint. No pooled-ratio substitution, early success or extra repeats. Every B arm records activation.
